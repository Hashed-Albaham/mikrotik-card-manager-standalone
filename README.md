# مدير كروت MikroTik — النسخة المستقلة

تجمع هذه النسخة بين **وضع محلي دون اتصال** وبين **خادم ويب ذاتي الاستضافة متعدد المستخدمين**. يعمل وضع PWA المحلي من دون خادم أو حساب، بينما يقدّم الخادم الحسابات وعزل البيانات وبوابة إدارة منفصلة.

## أوضاع التشغيل

| الوضع | الاستخدام | اتصال الراوتر |
|---|---|---|
| **PWA المحلي (`/offline`)** | التوليد، القوالب، PDF، RSC، TXT والتخزين المحلي المشفر | لا يوجد إرسال من المتصفح |
| **الويب الخادمي (`/`)** | حسابات المستخدمين وأجهزتهم وباقاتهم وقوالبهم ودفعاتهم المعزولة | لا يرسل أي دفعة تلقائياً |
| **بوابة المدير (`/admin`)** | اعتماد المستخدمين وتعطيلهم وتحديد الدور وتاريخ انتهاء التفعيل | لا تتصل بالراوتر |
| **سطح المكتب** | جميع وظائف PWA مع إرسال يدوي للدفعة عبر API أو API-SSL | اتصال محلي يبدأ عند ضغط زر الإرسال فقط |
| **Android APK** | جميع وظائف PWA مع إرسال يدوي عبر API على المنفذ 8728 ضمن الشبكة المحلية | اتصال محلي يبدأ عند ضغط زر الإرسال فقط |

> لا يتصل التطبيق بالراوتر عند فتحه، أو حفظ جهاز، أو إنشاء دفعة، أو تنزيل ملف، أو طباعة كرت. لا يبدأ أي اتصال إلا عند اختيار جهاز لدفعة محلية ثم الضغط على **إرسال الدفعة إلى MikroTik** والموافقة على التأكيد.

## تدفق الدفعات

تنشأ الدفعة محلياً أولاً، وتبقى قابلة للحذف أو الإلغاء أو التصدير أو الطباعة. عند اختيار إرسالها، يحفظ التطبيق نص RSC واحداً باسم الدفعة على الراوتر ثم يشغله مرة واحدة، ولا يرسل طلب API مستقلاً لكل كرت.

في RouterOS 6 تستخدم دفعات User Manager الصيغة التالية. يضبط `customer` على `admin` افتراضياً، ويمكن لاحقاً استبداله بالقيمة التي تستوردها من الجهاز.

```rsc
/tool/user-manager/user/add customer="admin" username="ZuFrNeEB" password="CIhwAane" comment="" location=""; 
/tool/user-manager/user/create-and-activate-profile customer="admin" profile=100 numbers=[find username="ZuFrNeEB"]; 
```

## وضع PWA دون اتصال

يتطلب التشغيل Node.js 22 أو أحدث وpnpm.

```bash
cd standalone
pnpm install
pnpm dev
```

افتح المسار `/offline` من العنوان المحلي الظاهر، وأدخل رمز PIN محلياً عند أول تشغيل. يستخدم التطبيق الرمز لاشتقاق مفتاح تشفير Web Crypto لبياناته المحلية؛ لا يوجد حساب مستخدم أو استرداد رمز عن بعد.

## الخادم متعدد المستخدمين وDocker

يتطلب هذا المسار Docker وDocker Compose. انسخ محتوى `ENVIRONMENT.example` في ملف محلي غير مرفوع اسمه `.env`، ثم استبدل كل قيمة تبدأ بـ`REPLACE...` بقيمة سرية خاصة بك. لا ترفع هذا الملف إلى GitHub.

```bash
docker compose up --build
```

ينتظر Compose قاعدة MySQL، ثم ينفذ خدمة `migrate` لإنشاء الجداول وأول مستخدم مدير من متغيرات `INITIAL_ADMIN_*`، وبعدها يبدأ خدمة `app`. افتح `http://localhost:3000` للمستخدمين و`http://localhost:3000/admin` للمدير.

لترحيل قاعدة MySQL خارج Docker، عيّن `DATABASE_URL` و`JWT_SECRET` و`INITIAL_ADMIN_USERNAME` و`INITIAL_ADMIN_PASSWORD` في بيئتك ثم نفّذ:

```bash
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm build
pnpm start
```

بعد وجود أول مدير لا يلزم تمرير متغيرات `INITIAL_ADMIN_*` عند إعادة التشغيل؛ فهي تستخدم فقط عندما لا توجد أي حسابات مدير.

| المتغير | مطلوب | الوصف |
| --- | --- | --- |
| `DATABASE_URL` | نعم للخادم | رابط MySQL مع ترميز `utf8mb4`. |
| `JWT_SECRET` | نعم | سلسلة عشوائية بطول 32 حرفاً أو أكثر لتوقيع الجلسات. |
| `RESOURCE_ENCRYPTION_KEY` | نعم عند حفظ جهاز | مفتاح AES-256 بصيغة Base64 (32 بايت بعد الفك) لتشفير كلمات مرور الأجهزة في قاعدة البيانات. |
| `INITIAL_ADMIN_USERNAME` | عند أول ترحيل | اسم أول مدير فقط. |
| `INITIAL_ADMIN_PASSWORD` | عند أول ترحيل | كلمة سر أول مدير، 12 محرفاً على الأقل. |
| `INITIAL_DEMO_USERNAME` و`INITIAL_DEMO_PASSWORD` | اختياريان عند أول ترحيل | ينشئان مستخدم تجربة نشطاً لمرة واحدة؛ يجب تقديمهما معاً وكلمة المرور 12 محرفاً أو أكثر. |
| `PORT` | اختياري | منفذ Express، الافتراضي 3000. |

> عند النشر على Coolify أو أي منصة Docker، عيّن **جذر المشروع** إلى `standalone` وأدخل القيم في واجهة الأسرار الخاصة بالمنصة. أما Vercel فهو serverless ولا يشغّل Docker Compose أو MySQL؛ استخدم قاعدة MySQL خارجية وحوّل الخادم إلى معالج serverless مستقل إذا كان Vercel شرطاً لديك.

## إنتاج PWA

```bash
pnpm build
pnpm preview
```

يحتوي ناتج `dist/` على Worker للتشغيل دون إنترنت. انشر هذا المجلد على خادم HTTPS محلي أو عام، ثم اختر **تثبيت التطبيق** من المتصفح. لا تعتمد وظيفة إنشاء PDF أو RSC أو TXT على نداءات شبكة.

## إنتاج Android APK

يتطلب هذا المسار JDK 21 وAndroid SDK API 36.

```bash
pnpm android:sync
cd android
JAVA_HOME=/path/to/jdk ANDROID_HOME=/path/to/android-sdk ./gradlew assembleDebug
```

يقع ملف APK التجريبي في:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

نسخة Debug مناسبة للاختبار الداخلي فقط. يلزم توقيع Release بمفتاحك الخاص قبل النشر أو التوزيع الإنتاجي.

## إنتاج تطبيق سطح المكتب

```bash
pnpm desktop:package
```

ينشئ الأمر مجلداً تنفيذياً في `dist/linux-unpacked/`. شغّل الملف التنفيذي منه مباشرة. يمكن تغليف المجلد بالطريقة المناسبة لنظام التوزيع الداخلي لديك.

## إعداد MikroTik الآمن

أنشئ مستخدم API مخصصاً بأقل صلاحيات لازمة، وقيد خدمة API بعنوان شبكة الإدارة فقط. استخدم منفذ API `8728` ضمن شبكة موثوقة، أو API-SSL `8729` في نسخة سطح المكتب عند الحاجة. لا تعرض API أو API-SSL للإنترنت العام.

## التحقق

```bash
pnpm check
pnpm test
pnpm build
pnpm db:migrate
```

تغطي الاختبارات مولد RSC المحلي، بما في ذلك الصيغة الدقيقة لـUser Manager 6 والفاصلة المنقوطة في نهاية كل أمر.

## الأمن والنسخ الاحتياطي

أنشئ نسخاً احتياطية دورية من وحدة MySQL في مخزن مشفر خارج الخادم. بدّل `JWT_SECRET` عند الاشتباه بالتسريب، ولا ترفع ملفات `.env` أو مفاتيح توقيع Android أو ملفات الشهادات إلى GitHub.
